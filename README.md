### 标签体系

标签不再是写死的 9 色色板，而是**可增删改的标签表**（`aurora.labels.v1`）：

```
{ id, name, color }   // 卡片只存 label id
```

- **内置 9 个**（id 与旧版写死色板一一对应，老数据零迁移）：`设计` · `待评审` · `紧急` · `阻塞` · `研发` · `调研` · `已完成` · `营销` · `杂项`
- **改色**：20 色预设板 + 原生取色器
- **改亮度自适应文字**：底色亮度 > 185 时标签文字改用深色（只覆盖内置黄色及其之上的浅色）
- **筛选栏只显示"正在用"的标签**，顺序跟随管理面板（内置色板序 + 自建按创建序）
- **导入导出**会一并带上标签表，跨浏览器可还原标签名称与颜色

## 三、技术决策与理由

| 决策 | 理由 |
|---|---|
| **手写 Pointer Events，不用 HTML5 Drag & Drop** | DnD 无法控制幽灵跟随精度、不支持自定义动画、触屏行为不可控 |
| **FLIP 实现让位动画** | 先测旧位置 → 改 DOM → 反向 `translate` → reflow → 过渡归零。这是"平滑滑开"而非"闪现"的唯一可靠做法 |
| **弹窗用 rect 反算起始帧** | 记录卡片 `getBoundingClientRect()`，反推 `translate + scale(sx,sy)`，`transform-origin: 0 0`，实现从卡片"长出来"的无缝感 |
| **列 `max-height` + `align-self:flex-start`** | 内容少不留白，超出则列内滚动。这样列内自动滚动才是真能力，而不是被撑高的假象 |
| **长列表只让列内内容区滚动，列头列脚固定** | `.list` 是 `flex-direction:column` + `max-height`，`.list-body{flex:1;overflow-y:auto}`。列头（标题/计数/进度条）与列脚（「添加卡片」）始终可见，滚的只有中间的卡片区。配合 `.list-body > .card{flex:none}`，卡片保持自然高度、**不塌陷**，超出部分由滚动条承载 |
| **官方 Actions，不用第三方 action** | 第三方 Pages action 有供应链风险；官方四步（checkout/configure/upload/deploy）已足够 |
| **构建戳注入 + 失败校验** | 线上直接显示版本号，一眼分辨"没部署"和"浏览器缓存"；锚点变更时 CI 直接失败，不静默产出 `dev` 戳 |
| **标签表独立存储，卡片只存 id** | 标签是"可被引用的实体"而非枚举常量。独立存 `aurora.labels.v1` 后，改名 / 改色只改标签表一处，不必遍历改写每张卡片的 `labels` 数组；删除标签时才批量清理引用。id 保持不变 → 改名后卡片引用不断、筛选状态也不丢 |
| **进度用独立 `status` 字段，不用普通标签** | 给 Agent 的契约必须**无歧义**：普通标签名可被用户改名、可能同名冲突；`status` 是固定枚举（todo/doing/review/done），Agent 写 `status:"review"` 不会有歧义，也不会污染用户的标签体系 |
| **图片存 IndexedDB，文本存 localStorage** | localStorage 只有 ~5MB 且按 UTF-16 计，base64 图片一张就 100–500KB，很快撑爆。IndexedDB 是磁盘级配额。描述里只留 `![说明](img:ID)` 引用，导出时再把 base64 内联进 JSON → **JSON 依然自包含，Agent 读一个文件就拿到全部信息** |
| **自写 Markdown 子集，不用第三方库** | 保持零依赖。**安全模型：用户文本先整体 HTML 转义，再在转义后的文本上做结构化替换，所有标签与属性都由解析器生成** → 用户内容无法逃逸成标签，因此落地时用 `innerHTML` 是安全的（**注意：不要改成直接塞用户原文**）。7 类攻击向量（script / img onerror / iframe / svg onload / style / a href=js / 闭合标签注入）已逐一验证，均不产生真实标签 |
| **纯本地存储，刻意不引入后端** | **主人明确要求「每个人都不同是最好的」（2026-10-20）**。看板数据留在各自浏览器的 localStorage，**不上传、不共享、不做账号系统**。全文零网络请求（无 fetch / XHR / WebSocket），验证方式见下方"零请求"自检。<br>**收益**：零成本、零隐私风险、离线可用；推代码上线不会动到任何人的数据；打开网址看到的是同一个应用、但里面是自己的看板。<br>**代价**：换设备 / 换浏览器 / 清缓存会丢 → **只能靠「导出 JSON」兜底**；也因此**团队协作看板这类需求明确不做**，不要主动提议加后端 |

## 四、踩坑记录（重要，避免重犯）

### 🐛 实现阶段修复的 4 个真实 bug

| # | Bug | 症状 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | **跨列拖动后数据丢失** | DOM 有 4 张卡，localStorage 只有 3 张，刷新后卡片消失 | `syncFromDom` 用 `l.cards.find()` 只在目标列原有卡片里找，跨列拖入的卡片被 `filter(Boolean)` 丢弃 | 先建全局 `id→card` 映射再回填 |
| 2 | **列表拖拽完全失效** | 每帧抛 `ReferenceError: d is not defined`，24 条控制台错误 | 清理 `activate()` 时误留 `const sb=d.node...` | 改为 `drag.node` |
| 3 | **列表换位错乱** | 拖拽后列序错乱、"添加列表"按钮跑到中间 | `target.nextElementSibling` 可能返回 `.add-list` 按钮 | 判定只遍历 `.list`，加 ±6px 容差 |
| 4 | **拖完误开弹窗** | 拖拽松手瞬间弹出详情窗 | `pointerup` 后紧跟的 `click` 命中卡片 | 加 `suppressClick` 标志 + 60ms 延时清除 |

### 🐛 布局与体验修正

| 问题 | 修法 |
|---|---|
| 列内容少时底部大片留白 | `.board-inner{height:100%}` + 列 `align-self:flex-start` |
| 弹窗描述框强制抢焦，橙色边框过于抢眼 | 移除自动 `focus()` |
| 子任务为空时进度条与提示重复 | 无子任务时隐藏进度条与百分比 |
| 窄屏描述框留白过大 | `min-height` 96px → 72px |
| **长列表卡片被压扁、不出滚动条** | `.list-body` 是纵向 flex 容器，卡片默认 `flex-shrink:1` 会被**压缩**而非让容器溢出；而 `.card` 带 `overflow:hidden` → 自动最小尺寸变成 0，卡片可被压到极扁，`overflow-y:auto` 永不触发。**修法：`.list-body > .card{flex:none}`**，卡片保持自然高度，超出部分由列内滚动承载 |

### ⚠️ 视觉层踩坑

| 坑 | 真相与修法 |
|---|---|
| **入口动画在某些渲染环境下不推进** | `.list` / `.card` 用 `animation:listIn/cardIn ... both`，`from` 帧是 `opacity:0`。若渲染器把 CSS 动画**冻结在 0% 帧**，整块看板就**完全不画出来**——DOM 查得到、控制台无报错、截图却全黑。**线上版与本地版都出现过**，且**同一页面过一会儿又能正常渲染**（说明是渲染时机/标签页可见性状态，不是代码）。**教训：入场动画不该独自承担"内容可见性"的责任**；诊断必须**先拿未修改版在同一环境对照**（同样空白 → 环境问题），确认后再决定要不要动代码 |
| **脉冲动画不能改写卡片自身的 animation** | 逾期脉冲最初写成 `.card.due-over{animation:cardIn...,duePulse...}` 并用 `box-shadow` 做关键帧 → 无限动画会**永久覆盖卡片自己的阴影**；动画若不运行还会留下残影。**修法：脉冲与闪烁统一走独立覆盖层 `.card-fx`**（`position:absolute;inset:0`，只动 `opacity`），完全不碰卡片自身的 `animation` 与 `box-shadow` |
| **覆盖层比 `box-shadow` 动画更安全** | 覆盖层在 `overflow:hidden` 的卡片内会裁掉外扩光晕，所以用「内描边 + opacity 脉冲」而非外扩 ring；副作用是任何环境下最坏结果只是"不闪"，不会"变丑" |

### 🐛 浮层与排序

| 坑 | 真相与修法 |
|---|---|
| **外部点击关闭浮层，别把更上层的浮层也算成"外部"** | 删除标签要二次确认，确认框（z 1500）盖在管理面板（z 1350）之上。若外部点击判断只写 `!panel.contains(e.target)`，**点确认框的按钮会把管理面板一起收掉**——用户连删几个标签就得反复重开。**修法：额外排除 `.confirm,.menu,.pop`** |
| **别用 `localeCompare` 给中文标签排序** | `localeCompare(b,'zh')` 在不同 Chromium / ICU 版本下顺序差异大，实测得到「待评审, 调研, 回归测试, 紧急…」这种完全不符合拼音直觉的结果。**修法：按「管理标签」面板的数组顺序输出**——内置标签保持色板序，自建标签按创建序追加，行为确定可预期 |
| **浅色阈值别拍脑袋** | 标签文字要按底色亮度切深/浅色。阈值取 150 会把绿/橙/青/粉统统翻成深色字，与卡片上的白字 chip 打架。**取 185**：只影响内置黄色 `#f5c451`（原版就特判过它），其余保持白字，视觉一致 |
| **文件桥的 `board.json` 必须进项目 `.gitignore`** | 文件桥把工单数据放在**项目目录**里（Agent 要能读到）。而项目目录通常是 git 仓库 → `git add -A` 会把工单数据（还带 base64 图片）一起提交，仓库瞬间膨胀。**接入时第一件事就是给目标项目加 `.gitignore` 条目** |
| **自动化传文件的限制别当成功能 bug** | 本机内置 Browser 的 `upload_files` 对 `<input type="file">` 报 "Browser action failed in Electron main"，原生文件选择框也无法被驱动。**这不代表功能有问题** —— 改用「降级路径」（导出/导入 JSON）或在 Node 侧直接验证数据契约，**别为了迁就测试工具去改产品代码**。同理，`<input type="file" hidden>` 用 `display:none` 会让它无法被自动化定位，改成视觉隐藏（`.vh`）反而更利于无障碍与测试 |

### 🐛 浮层遮挡与自动化

| 坑 | 真相与修法 |
|---|---|
| **浮层会盖住别的按钮** | 提醒中心锚在顶栏第一行的铃铛上，向下展开会横跨第二行，**正好盖住工具条上的「管理标签」按钮**（z 1350 > 顶栏控件），用户点不到。**修法：面板下沿改到整个 `.topbar` 之下**（`Math.max(r.bottom+8, topbar.bottom+8)`），保证任何顶栏控件都不会被浮层压住 |
| **有无限动画的页面上，自动化 click 会超时丢事件** | 背景 `aurora` 的 `float` 22s 无限循环让页面永远"不稳定"，自动化工具等稳定 → **5 秒超时后丢弃事件**，表现为"按钮点了没反应"，看起来像代码 bug。**判据：click 耗时接近 5s 就是这个症状**（正常 200–800ms）。**修法：先发一个按键/做一次交互让页面进入可响应状态再点**；或改用 DOM 查询断言代替点击。**别把它误判成"线上坏了"——先拿本地同一份文件、同一视口做对照** |

### ⚠️ 部署阶段的坑

| 坑 | 真相 |
|---|---|
| **Pages 缓存** | GitHub Pages 走 Fastly CDN，`Cache-Control: max-age=600`。10 分钟内浏览器**压根不发请求**，普通 F5 无效，须 `Ctrl+F5` |
| **CI 失败 ≠ 代码有问题** | 本项目首次部署失败于 `Setup Pages`，因 `has_pages: false`（Pages 未启用）。**必须做步骤级定位**，别一看到红叉就改代码 |
| **根路径 404** | 仓库必须含 `index.html`，`path: .` 全量上传也救不了 |
| **构建戳注入** | 依赖 `id="build-stamp">dev<` 精确锚点。校验判据是「**实际戳 == 期望戳**」而非「dev 是否还在」——后者在锚点被改名时会误判通过（`sed` 注到新名字，旧串自然找不到）。锚点被改名或删除时 CI 直接失败，不会静默产出 `dev` 戳 |
| **Node 20 弃用警告** | Actions 已被强制跑在 Node 24 上（旧版本 action 触发警告）。已升级为最新：`checkout@v7`、`configure-pages@v6`、`upload-pages-artifact@v5`、`deploy-pages@v5` |
| **GitHub API 匿名限流** | 公开仓库的 API 免鉴权，但配额只有 **60 次/小时/IP**。高频轮询会直接撞 403（本次 25 秒一轮，连查十几分钟就打满了）。**修法：判定"部署是否生效"优先抓线上页面的构建戳**——那才是权威信号，且不吃 API 配额；API 只用来做步骤级定位。轮询间隔 ≥ 60 秒 |
| **Pages 并发组不保证 FIFO** | `concurrency: {group: pages, cancel-in-progress: false}` 让多个 run **串行**执行，但**顺序不保证**：实测较新的 `2c639a2` 反而先于较旧的 `d271419` 跑完。**推多个提交时只有最后一轮落地后线上才是最终态**，中途看到构建戳变了不能当作"已上线" |

### 📌 方法论教训

1. **验证不能只看工具返回值** —— 判断"线上是新版本"要抓真实内容逐字节比对，不是看 HTTP 200。
2. **公开仓库的 GitHub API 免鉴权** —— 判断"部署跑没跑、卡哪步"最快的手段：
   ```bash
   curl -s "https://api.github.com/repos/<owner>/<repo>/actions/runs?per_page=1"
   curl -s "https://api.github.com/repos/<owner>/<repo>/actions/runs/<id>/jobs"   # 步骤级
   curl -s "https://api.github.com/repos/<owner>/<repo>" | grep has_pages
   ```
3. **测完必须收尾** —— 后台服务不留残留。判定标准是"端口真的空了"，不是"工具返回成功"。
4. **校验逻辑本身要被校验** —— 构建戳的守卫最初写成「查 `dev` 还在不在」，看起来合理，但锚点一旦被改名，`sed` 会注到新名字上、旧串自然找不到 → **守卫误判为通过，静默失效**。做反向演练（故意破坏输入，确认守卫真会拦住）才发现。**判据要落在"结果等于期望值"，不是"坏值是否消失"**。
5. **改坏 vs 环境坏，先做对照再下结论** —— 本次改完看板整块不显示，第一反应是"我改坏了"。**先拿线上未修改版在同一环境打开**（同样空白 → 环境问题），再回头查自己的改动。否则会把环境问题当成自己的 bug 去"修"，白费一轮还可能改坏原本正常的代码。
6. **自动化写不进原生日期框，不代表功能坏了** —— `<input type="date">` 的 `fill` / `type` 在浏览器自动化里普遍失败（值不是纯文本字段）。此时改走**同一条业务链路的其他入口**（如「清除日期」按钮同样触发 `save()` + 局部刷新），验证真实逻辑，而不是硬怼输入框。
7. **写 `.ps1` 给 PowerShell 5.1 跑，必须存 UTF-8 带 BOM** —— 5.1 会把无 BOM 的 `.ps1` 按系统 ANSI 解码，脚本里的中文注释直接把解析器打挂，报一堆"意外的标记 ')'"这类看不懂的错。补 BOM：`[System.IO.File]::WriteAllText($p,$txt,(New-Object System.Text.UTF8Encoding($true)))`。
8. **台账里的数字会漂移，能自动核对就别手写** —— 本次"约 75 KB"在两次大改后已变成 98.7 KB，半年后没人会记得回头改。**修法：把这类声明写成断言**（见第六章 `verify.ps1`），让失真主动暴露，而不是等人来读。
9. **flex 容器里"该滚动"和"该压扁"只差一个 `flex:none`** —— 纵向 flex 容器默认会让子项**收缩**而不是溢出滚动；子项一旦带 `overflow:hidden`，自动最小尺寸归零，就能被压到任意扁。症状极具迷惑性：**看起来"内容被等分到容器高度"，而不是"没有滚动条"**。**诊断要看真实渲染高度，不要只看有没有滚动条**；修法是给需要保持自然尺寸的子项显式 `flex:none`。**反向演练**：在测试副本里把修复覆盖掉，量一下高度是否塌成同一个值——塌了才说明根因找对了 |

## 五、Agent 工单流用法（bug 异步流转）

**目的**：把本面板当作 Agent 的**异步工单系统** —— 主人随时发布 bug，Agent 串行处理，主人有空时逐个复查。避免"agent 改一个 bug 就占住对话"的串行等待。

### 角色与状态机

```
主人发布 ──▶ 待处理 ──▶ 处理中 ──▶ 待复查 ──▶ 已确认
（建卡片）      │          │          │        （主人复查通过）
                └──────────┴──────────┘
                 Agent 领取 → 改代码 → 改状态 → 回写文件
```

| 维度 | 表达方式 | 说明 |
|---|---|---|
| **哪个项目** | 列表名 / 哪个 `board.json` | 一个文件 = 一个项目 |
| **到哪一步** | `card.status` 字段 | **固定枚举**，不是普通标签 → 给 Agent 无歧义契约 |
| **是什么类型** | `card.labels` | 普通标签（可自定义名称与颜色） |

**复查工作台**：顶栏「状态」筛选栏点「待复查」→ 跨所有列表筛出待复查的卡片；统计栏也有「待复查 N」。

### 通道：本地 JSON 文件（每个项目一份）

面板数据在浏览器 localStorage 里，Agent 用另一个浏览器 profile **读不到**。所以用**本地文件做桥**：

1. 顶栏点 **「文件同步」**（链条图标）→ 「新建同步文件…」→ **存到该项目目录**，例如
   `C:\Users\yutue\WorkBuddy\trello看板\board.json`
   （每个项目一个文件，互不干扰；Agent 在哪个项目干活就读哪个文件）
2. 连接后**双向自动同步**：
   - 面板任何改动 → 800ms 防抖 → 写文件（`rev` 自增）
   - 每 4 秒 + 窗口聚焦 → 读文件；**只有 `rev` 更大的一方才会覆盖另一方**
3. 不支持 File System Access API 的浏览器（Safari/Firefox）→ 用顶栏「导出 / 导入 JSON」手动同步（同一份格式）

> ⚠️ **接入项目务必把 `board.json` 加进那个项目的 `.gitignore`** —— 否则 `git add -A` 会把工单数据（还带 base64 图片）一起提交，仓库瞬间膨胀。

### 文件格式（Agent 直接读写这个 JSON）

```json
{
  "app": "aurora-board", "version": 1, "rev": 12,
  "updatedAt": "2026-10-21T01:20:00.000Z",
  "title": "Aurora Board",
  "lists": [{
    "id": "l_x", "title": "todo-app 项目", "color": "#ff6a3d",
    "cards": [{
      "id": "c_x", "title": "搜索无结果时白屏", "status": "review",
      "desc": "## 现象\n\n搜索无匹配时页面直接白屏。\n\n![截图](img:img_1)",
      "labels": ["lb_new"], "due": "", "subtasks": [], "comments": []
    }]
  }],
  "labels": [{ "id": "lb_new", "name": "回归", "color": "#ff5c5c" }],
  "images": { "img_1": "data:image/jpeg;base64,..." }
}
```

| 字段 | 含义 |
|---|---|
| `rev` | **单调递增修订号**。Agent 改完自增；面板据此判断"要不要覆盖我的界面"（`文件.rev > 本地.rev` 才应用） |
| `desc` | Markdown 子集源码；图片用 `![说明](img:图片ID)` 引用，base64 实体放 `images` 里 |
| `images` | Agent 写截图时把 base64 放这里；面板导入时拆进 IndexedDB，导出时再内联回去 |
| `labels` | 标签表（名称 + 颜色）。改标签名/色只改这里，**不动卡片** |
| `status` | `todo` / `doing` / `review` / `done` |
| **兼容性** | 旧格式（无 `status` / `labels` / `images`）照样能导入，缺字段自动补默认值 |

### Agent 侧操作约定

```powershell
# 1) 取待处理的 bug（含描述与截图）
$j = Get-Content board.json -Raw | ConvertFrom-Json
$j.lists | ForEach-Object { $_.cards } |
  Where-Object { $_.status -in 'todo','doing' } |
  ForEach-Object { "【$($_.title)】$($_.desc)" }
# 截图：$j.images 里的 base64 → 写成 png 文件再读

# 2) 改完代码 → 标记为待复查 → 回写
$j.lists[0].cards[0].status = 'review'
$j.rev = $j.rev + 1
$j.updatedAt = (Get-Date).ToUniversalTime().ToString('o')
$j | ConvertTo-Json -Depth 10 | Set-Content board.json -Encoding UTF8
```

面板在 4 秒内自动拉到（`rev` 更大即应用），并提示「已同步外部更新」。

### 描述里的图片从哪来

- **主人贴图**：在描述框里**直接粘贴 / 拖入 / 点「图片」按钮** → 面板压缩后存 IndexedDB
- **Agent 写图**：把 base64 放进 JSON 的 `images`，描述里写 `![说明](img:ID)` → 面板渲染成图
- 两种来源在面板里**渲染完全一致**，互不干扰
